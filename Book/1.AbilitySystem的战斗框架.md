# AbilitySystem 的战斗框架

## 一. 概述

AbilitySystem 是参考原神 GAS（Gameplay Ability System）设计的战斗框架。在「Ability / Modifier / Mixin」三层之上，还包含四个横切系统，是框架里最易配错、也最值得先理解的部分：

- **GameplayTag 与层数系统**：用 `GameplayTags`（long 位标记）表达"身上有什么状态、各几层"，由 `ControlComponent` 统一聚合成 `tagMask` / `tagStacks` / `deniedMask`。
- **能力剥夺（控制）系统**：基于标记派生"能不能动 / 能不能放技能"，与"处于什么状态"拆成两根互不相通的轴。
- **被选中性 / 强制目标（选择轴）**：`selectOf` / `forcedOf` 两张表回答"别人能不能选中我 / 我必须打谁"，方向与"我能做什么"相反，独立成第三条轴 —— 虚化、潜行、嘲讽走这条，不走剥夺位。
- **伤害吸收（护盾）系统**：把修饰器状态字典当作伤害池，`IDamageAbsorber` 接口解耦"吸收"与"数据存哪"。
- **霸体 / 破霸体**：把"削韧性"做成部位 × 属性 × 值的扁平三元组，配 `NumericComponent` 的数值变化监听。

运行时由 `AbilitySystem`（Manager）统一驱动，挂载在实体上的 `AbilityComponent` 管理当前实体的所有 Ability 实例；控制 / 标记 / 免疫 / 选择轴（被选中性、强制目标）的聚合与广播，由 `ControlComponent` 在一个入口 `Rebuild` 里一次遍历算完。

## 二. 配置说明

### 1. FSM 状态机

在本工程中 FSM 用于控制游戏角色的行为，例如玩家、怪物等实体的移动、攻击，采用动画状态机 AnimatorController 来编辑，最后导出成 json 文件，在游戏运行时使用 FsmComponent 加载配置文件然后驱动。同时会导出一份专门用于播放动画的纯净版 AnimatorController。

编辑动画状态机 FSM 的目录在 `Assets/AssetsPackage/Unit/XXX/Edit/FsmConfig.controller`，路径格式是固定的，写好后右键该文件 `工具/状态机导出` 即可。导出 json 文件和纯净版所在位置 `Assets/AssetsPackage/Unit/FsmConfig.json` 和 `Assets/AssetsPackage/Unit/XXX/Animations/FsmConfig.controller`。最后需要在 `Excel/Unit.xlsx` 表里配置相对路径才能使用。

**支持 Timeline 联合使用。** 目录需和编辑动画状态机 FSM 的目录相同，一个 `.playable` 文件对应一个动画状态机的状态，`.playable` 文件名和动画状态机的状态名保持一致。编辑时，拖入对应动画片段，使 `.playable` 文件长度和对应动画片段长度相同，然后在上面添加自定义的 Marker（如 `ExecuteAbilitySignal`）。最终会随动画状态机一起导出到 json。

相关代码：`Code/Game/Component/Fsm/`（Fsm.cs / FsmComponent.cs / FsmState.cs / FsmState.Timeline.cs）

### 2. Ability / Modifier

Ability，能力，可以把它理解为用于给策划配置各种逻辑的触发器或监听器以及数值。它分为 **ActorAbility**（以下简称 Ability）和 **ActorModifier**（以下简称 Modifier），它们的功能逻辑几乎一样，区别在于 Modifier 作为 Ability 的配置子项，只能由 Ability 来触发添加。

Ability 在 `Assets/AssetsPackage/EditConfig/Abilities` 配置。

**ConfigAbility 字段说明：**

| 字段 | 说明 |
|------|------|
| AbilityName | 全局唯一，用于索引 |
| AbilitySpecials | 在此 Ability 生效的参数配置（施法者共享，一份） |
| AbilityMixins | 各种触发器或监听器，可根据需求自行扩展（挂这里也能配常驻免疫） |
| Modifiers | 准备用来添加的整块逻辑 |

**ConfigAbilityModifier 字段说明：**

| 字段 | 说明 |
|------|------|
| ModifierName | 该 Ability 唯一，用于索引 |
| Duration | 持续时间，-1 无限，0 瞬时，>0 有限时间，单位 ms |
| StackingType | 叠加类型，Duration 不为 0 时有效 |
| StackLimitCount | 叠加上限，StackingType 为 Multiple 时有效 |
| Tags | **状态标记**（`GameplayTags`）：本修饰器归属哪些标记。上限、剥夺、打断、被选中性 / 强制目标全部由标记派生，不在这里配 |
| ModifierSpecials | **修饰器级状态字典**（每个目标 × 每次施加各一份），用于盾量 / 剩余次数 / 充能层数等数据 |
| Mixins | 各种触发器或监听器，可根据需求自行扩展 |
| Properties | 用于修改玩家数值（按层增量生效） |

> **层数单一真相源**：`ActorModifier.StackCount` 是层数的唯一来源。`Properties` 按层缩放、`ControlComponent.tagStacks` 聚合、`TagStackValue` 读取全部由它驱动。不要在状态字典里另配一个"层数" key —— 两份记账不会联动，迟早对不上。

### 3. Mixin 体系

Mixin 是 Ability/Modifier 的核心扩展机制。每种 Mixin 负责监听一种事件并在触发时执行配置的 Action 列表。

**当前已实现的 Mixin（`Code/Game/Component/Ability/Mixin/`）：**

| Mixin | 触发时机 |
|-------|---------|
| `AttachToNormalizedTimeMixin` | 动画归一化时间达到指定值 |
| `AttachToStateIDMixin` | 进入指定 FSM 状态 |
| `DoActionAfterAddMixin` | Ability/Modifier 添加后 |
| `DoActionAfterAttackMixin` | 攻击命中后 |
| `DoActionAfterBeAttackMixin` | 被攻击后 |
| `DoActionAfterLoadObjectMixin` | 对象加载完成后 |
| `DoActionBeforeAttackMixin` | 攻击前 |
| `DoActionBeforeBeAttackMixin` | 被攻击前 |
| `DoActionBeforeRemoveMixin` | Ability/Modifier 移除前 |
| `DoActionByExecuteMixin` | 手动 Execute 时 |
| `DoActionByGadgetStateMixin` | Gadget 状态变化时 |
| `DoActionByStateIDMixin` | FSM 状态匹配时 |
| `DoActionByTickMixin` | 定时 Tick |
| `DoActionOnColliderBoxMixin` | 碰撞盒事件 |
| `DoActionOnInputMixin` | 输入事件 |
| `DoActionOnInteeTouchMixin` | 交互触发 |
| `DoActionOnTriggerMixin` | 触发器事件 |
| `DoActionOnUseSkillMixin` | 使用技能时 |
| `DoActionOnFsmTimelineTriggerMixin` | FSM Timeline 上的 Marker 触发 |
| `DoActionOnEntityTagsChangeMixin` | **[新] 监听状态标记变化**（`EntityTagsChanged`） |
| `DoActionOnControlStateChangeMixin` | **[新] 监听能力剥夺变化**（`ControlStateChanged`） |
| `DoActionOnSpecialsChangeMixin` | **[新] 监听修饰器状态字典越过阈值**（破盾/充满/耗尽） |
| `DoActionOnNumericChangeMixin` | **[新] 监听实体数值变化**（霸体/破霸体相关） |
| `AbsorbByStateMixin` | **[新] 把修饰器状态当作伤害池，实现护盾吸收** |
| `ImmuneMixin` | **[新] 免疫标记：命中则拒绝施加，可配免疫成功 Actions** |

> **两条轴不要混用**：监听"被眩晕 / 灼烧叠层 / 护盾破了"用 `DoActionOnEntityTagsChangeMixin`（GameplayTags 轴）；监听"能不能动了 / 被完全钉死"用 `DoActionOnControlStateChangeMixin`（ControlFlag 轴）。两条轴互不相通，后者刻意没有按能力位过滤的字段。

### 4. Action 体系

Mixin 触发后执行配置的 Action 列表。Action 配置位于 `Code/Module/Config/Ability/Action/`，当前约 40 种，常用包括：

- `ApplyModifier` — 添加 Modifier
- `RemoveModifier` — 按 `(施法者 ability 名, ModifierName)` 精确移除一条
- `RemoveModifierByTag` — **[新] 按标记消耗/移除 Modifier**（`Consume`/`Clear`/`Keep` 三模式）
- `CreateBullet` / `CreateGadget` — 创建子弹 / 生成物
- `TriggerAttackEvent` — 触发攻击判定
- `ModifyAttackResult` — **[新] 修改本次这一击的结算参数**（伤害/倍率/暴击/取消）
- `SetSpecial` / `AddSpecial` — **[新] 写状态字典**（Ability 级或修饰器级）
- `SetNumericValue` — **[新] 写实体数值**（破霸体扣韧性等）
- `SetFsmParam` — 设置 FSM 参数
- `TryDoSkill` / `AddSkillInfo` / `SetSkillInfo` — 释放技能 / 注入技能 / 原子装配技能
- `KillSelf` — 自杀

**ConfigAbilityAction 公共字段说明：**

| 字段 | 说明 |
|------|------|
| Predicate | Targetting 目标重新选定生效前判定是否满足条件，不满足则不执行 |
| Targetting | 重新选定 Action 的目标 |
| OtherTargets | Targetting 为 Other 时有效 |
| PredicateForeach | Targetting 目标重新选定生效后对每一个目标进行判定是否满足条件，不满足则不执行 |

### 5. 数值与状态取值体系（BaseValue / Predicate）

所有"算一个数"的地方统一走 `BaseValue` 派生类，所有"判定条件"统一走 `ConfigAbilityPredicate` 派生类。新增数值来源或判定逻辑时**只扩这两个家族**，不要在 Action 里写死。

**BaseValue 家族（取值）：**

| 类 | 读什么 | 关键字段 |
|----|--------|---------|
| `NumericValue` | 实体级 `NumericComponent`（所有来源共用一个池）：ATK / HP / EN | `NumericType` id（如 1012=EN、1001=Hp） |
| `TagStackValue` | 某个 `GameplayTags` 当前层数（聚合自 `ControlComponent`） | `Tag`（单个原子标记）、`Source`、`Min`（默认 1，不是 0） |
| `SpecialValue` | 状态字典的某个 key（盾量 / 充能 / 层数） | `Key`、`Target`（Auto/Modifier/Ability）、`Default` |
| `OperatorValue` | 把多个 BaseValue 做运算（如 `Shield/MaxShield` 得比例） | 左右操作数 + 运算符 |
| `FormulaValue` | 复杂公式 | — |
| `SingleValue` | 常量 | 数值 |
| `ZeroValue` | 0 | — |

> **TagStackValue 要点**：① 多来源共享一个池（火法 3 层 + 环境火 2 层 → 读 5）；② `Stack`/`Multiple` 都正确（读聚合值而非单个实例）；③ 天然封顶，不要自己再 clamp（上限在 `GameplayTagMeta`，改配置无效）；④ `Min` 默认 1 —— 0 一旦进乘法会把伤害静默乘成 0 且无日志，宁可默认值偏大也好过安静出错。
>
> **SpecialValue 要点**：`Auto`（默认）有修饰器就读修饰器、否则读 Ability；**不会"读不到就换层"**，修饰器存在但 key 漏配只报错返回 `Default`，避免张冠李戴。
>
> **StackSource（TagStackValue.Source）**：`ModifierOwner`（默认，DoT 挂受击者身上用这个）/ `Caster`（读自己身上的 buff 层数）/ `Attacker`（本次结算攻击者）。实战里攻击者、Ability、Modifier 常指向不同实体，必须显式选，否则猜错表现为稳定的 0。

**ConfigAbilityPredicate 家族（条件）：**

| 类 | 判定 |
|----|------|
| `ByNumericCompare` | 实体某数值与阈值比较（`NumericType` id + `CompareMode` + `Value`），如"韧性归零伤害翻倍""血量<30%处决" |
| `BySpecialCompare` | **[新] 状态字典值与阈值比较**（`Value`=BaseValue，`Threshold`），如"盾量>0 才允许破盾反击""灼烧>=3 才允许引爆" |
| `BySkillReady` | 技能是否就绪 |
| `ByOr` / `ByAnd` | 组合条件 |

> **BySpecialCompare vs ByNumericCompare**：前者读"修饰器级 / 施法者级"状态字典（盾量、剩余次数、充能层数这类**每个目标每次施加各一份**的数据），后者读实体级 `NumericComponent`。要"盾量/上限>0.3"这类比例判断，填 `OperatorValue` 做运算即可，无需加专用谓词。

## 三. GameplayTag 与层数系统

### 1. 标记的段划分（`GameplayTags` 底层是 long 位域）

- **段 1（bit 0..15）控制身份**：眩晕 / 定身 / 沉默 / 减速 … `GameplayTagMeta.ControlKindMask` 覆盖整段，`HasTag(ControlKindMask)` 等价于"是否被控"。
- **段 2（bit 16..23）自身动作锁**：吟唱 / 蓄力 / 僵直 / 后摇。
- **段 3（bit 24..63）状态标记**：灼烧 / 中毒 / 护盾 … `StateFlagMask`。

段 3 已用位（新标记一律往后追加，位值发布即冻结）：

| bit | 标记 | 语义 |
|-----|------|------|
| 24~28 | `Burn` / `Poison` / `Bleed` / `Vulnerable` / `Shield` | 元素异常与增益（`Burn` 默认封顶 5 层） |
| 29 | `Rush` | 正在冲刺 / 突进 |
| 30 | `Untargetable` | 不可选中（虚化 / 潜行）：`selectOf = -1` |
| 31 / 32 | `Taunted` / `TauntedHard` | 软强制攻击施加者：`forcedOf` = 1 / 2 |
| 33 | `Invincible` | 无敌：纯身份标记，伤害拦截靠修饰器的受击前钩子 |
| 34~63 | 预留 | 元素异常 / 增益 / 减益的长期增长区 |

> 段 2（16..23）现用 `Chant` / `Charge` / `Stagger` / `Recover` / `NoSprint`，bit 21..23 预留。`Untargetable` 原先落在段 2 的 bit 21，已迁到段 3 —— 段 2 的语义是「自身动作锁：我动不了」，装不下「别人选不中我」。

组值 `AllControlKind` / `AllActionLock` / `AllStateFlag` 可一次性勾选整段，新增标记自动被覆盖，不用回来改配置。

### 2. 标记 → 行为 全部由 `GameplayTagMeta` 收敛（加一种状态只改这一处）

| 表 | 回答 | 备注 |
|----|------|------|
| `tierOf` | 这个标记剥夺哪些能力（`ControlFlag`） | 眩晕 = Move\|Turn\|CastSkill\|Attack\|Sprint 全禁，配置只写 `Tags=Stun` |
| `maxStackOf` | 最多几层 | **上限属于标记不属于修饰器**（"灼烧最多 5 层"全局一致） |
| `levelOf` | 表现等级 | **等级属于标记**，同源不同来源的同一状态动画一致 |
| `interruptOf` | 生效时是否打断当前动作 | 不能从 `tierOf` 推导（吟唱自锁但不打断自己、魅惑不剥夺却要打断） |
| `selectOf` | 别人能不能选中我（候选侧） | `<0` 不可选（越负越硬）/ `0` 中性 / `>0` 吸引；**只登记段 3** |
| `forcedOf` | 我必须打谁（施加侧） | `>0` = 被迫以施加者为目标，数值即优先级；**只登记段 3** |

后两张表是「选择轴」，与 `tierOf` 是两条互斥的轴：同一个标记不能既表示"我动不了"又表示"别人选不中我"。

未登记的标记按"不剥夺、不可叠、可选、无强制"处理，所以加标记不必同步改表，只有需要特殊语义才登记。加载期校验一律报错而不是等到行为诡异：修饰器挂了两个控制身份、Tags 含枚举不存在的位、段 3 状态登记了剥夺/打断、选择轴登记在非段 3 或与剥夺/打断同挂。

### 3. 聚合与读取（唯一出口在 `ControlComponent`）

`modifier 增删 / 叠层 → AbilityComponent.NotifyModifiersChanged() → ControlComponent.Rebuild() 全量重算 deniedMask / tagMask / tagStacks / selectionPriority / forcedTargetId（一次遍历）→ 有变化才广播 → 打断源从无到有时执行一次打断`。

- `CanDo(ControlFlag)`：能不能执行某项行为（**唯一判定出口**）。传单个能力位；传组合位会变成"全被禁才算禁"。
- `IsControlled`：是否被控（段 1 任一位）。**不要用 `DeniedMask != None` 代替**——吟唱时能力被锁但没被控，减速时被控但能力没被锁，两者不互推。
- `IsHardControlled`：五项能力是否全禁（完全钉死）。
- `HasTag` / `HasAllTags`：是否挂指定标记（组合值=命中任一 / 全部）。
- `GetTagStack(tag)`：某标记层数总和（**只能传单个原子标记**，组合值会报错）。
- `GetTagMaxStack` / `GetTagRoom`：上限 / 还能加几层（多位时原子，要整组都能加一层才算有余量）。
- `SelectionPriority`：候选侧选择权，`<0` 不可被选中。**选敌过滤一律读它**（`TargetHelper.CanBeSelected`），不要自己翻标记位。
- `TryGetForcedTarget(out id)`：强制目标 id。只给 id 不给实体 —— 实体随时会销毁，调用方自己 `Get` 后校验存活，缓存实体引用是这类 bug 的标准来源。
- 跨系统请订阅 `MessageId.EntityTagsChanged` / `MessageId.ControlStateChanged` / `MessageId.SelectionChanged`；同实体内部用 `OnTagsChanged` / `OnMaskChanged` 回调省一次消息查找。

## 四. 能力剥夺（控制）系统

`ControlComponent` 同时维护**三根互不相通的轴**：

| 轴 | 载体 | 含义 | 出口 |
|----|------|------|------|
| 许可轴 | `ControlFlag`（由标记 `tierOf` 派生，**配置无手写入口**） | 被剥夺的能力并集：我能不能动 | `CanDo` |
| 标记轴 | `GameplayTags` | 身上有哪些状态、各几层 | `HasTag` / `IsControlled` / `GetTagStack` |
| 选择轴 | `GameplayTagMeta.selectOf` / `forcedOf` | 别人能不能选中我 / 我必须打谁 | `SelectionPriority` / `TryGetForcedTarget` |

```text
被减速     → IsControlled=true，  CanDo(Move)=true    （控制身份，但不剥夺）
正在吟唱   → IsControlled=false， CanDo(Move)=false   （自身锁，不算被控）
```

"被控了没"一律问 `IsControlled`，"能不能动"一律问 `CanDo`。身份与剥夺是同一份标记数据推导出的两个视图，所以不可能出现"挂了眩晕却还动得了"的脱钩。

**免疫（`ImmuneMixin` / `ConfigImmuneMixin`）**：挂在 Mixin 上（Ability 或 Modifier 都可），afterAdd 注册、beforeRemove 注销到 `ControlComponent` 的 0~2 项小表。`ApplyModifier` 入口按 `TryGetImmune` 点查，命中则**整条拒绝**（修饰器实例根本不创建，不打断施法、不扣属性、不占层数池）。免疫只挡"新的"，不清已挂状态；要清请配 `RemoveModifierByTag`。免疫成功可配 `Actions`（抵抗表现 / 扣次数 / 反击）。有限次数 = `Actions` 里 `AddSpecial` 扣 + 另挂 `DoActionOnSpecialsChangeMixin` 监听归零后 `RemoveModifier`。

### 1. 选择轴（被选中性 / 强制目标）

前两根轴都在回答"我"的问题，选择轴方向相反：候选侧是别人看我的视角，施加侧是我被谁驱使。

- **为什么不复用 `ControlFlag.BeSelected`**：方向相反（"我能做什么" vs "别人能不能选我"），而且需要正负势与优先级仲裁，单向布尔位表达不了。该位已弃用、位值保留勿复用，全库无读者。
- **聚合**：候选侧取最负（任一排斥即排斥，安全优先），施加侧取最强；同级取后施加者（`modifier.Id` 递增，连续两次嘲讽时最后一次说了算）。
- **四步仲裁**：① 强制轴 → ② 候选过滤（`TargetHelper.CanBeSelected`）→ ③ 吸引优先 → ④ 默认角度 / 距离。
- **软强制**：嘲讽目标不可用（死亡 / 不可选中 / 非敌对）时回落常规选敌，不是硬锁 —— 硬锁会在目标消失时把人钉在原地。
- **两处消费者**：`CombatComponent.SelectAttackTarget`（主动选敌；强制块放在 early-return 之前，才能顶掉已有锁定）、`ConfigSelectTargetsByRange`（范围选敌）。AOE 走 `DamageClose` 直连，**不经过**选择轴。
- **缓存同步**：`MessageId.SelectionChanged` 回调里立即改写 / 清空 `attackTarget`。缺这一步的表现是"被嘲讽了，但这一发还打老目标"。

要新增"诱饵 / 吸引"这类效果，只需给新标记登记 `selectOf = 1`，选敌代码零改动。

### 2. 虚化与无敌必须拆成两个状态

| 状态 | 标记 | 实际做的事 |
|------|------|-----------|
| 虚化 `Vanish` | `Untargetable`（`selectOf = -1`） | 只影响"被主动选中 / 范围选敌"，AOE 仍能扫到 |
| 无敌 `Invincible` | `Invincible`（纯身份标记，不派生剥夺） | 修饰器挂 `ConfigDoActionBeforeBeAttackMixin` → `ModifyAttackResult{Cancel:true}`，命中即被吞 |

合并成一个状态会丢掉中间态：虚化者被 AOE 扫到是**对的**（否则隐身等于免伤 + 免控 + 免 AOE），掉不掉血由无敌单独决定。用 `ControlFlag.Attack` 表达无敌也不可行 —— 施法门禁会连角色自己的普攻一起锁死。

配置侧（`KeQing.json` 的 `_Hide` / `_Show`）：

- `_Hide` 三条修饰器：`NoSprint`(1<<20) / `Vanish`(1<<30) / `Invincible`(1<<33，带受击前钩子)，三次 `ApplyModifier`。
- `_Show` 一次 `RemoveModifierByTag{Tags = 1<<20 | 1<<30 | 1<<33, Mode = Clear}` 一起清 —— `CollectStackTargets` 的判定是"任一命中"，一次 Clear 可清多个标记。
- `Mode` 必须显式填 1（`Clear`），填 0 会被序列化省略成默认的 `Consume`。

## 五. 伤害吸收（护盾）系统

把修饰器状态字典当作伤害池，与"数据存在哪"解耦。

- **`IDamageAbsorber`**：`AbsorbPriority`（数值小的先扣，**专盾必须排通用盾前面**，否则通用盾会把伤害吃光、专盾永远等不到属于自己的那一下）、`AbsorbDamage(damage)` 返回**实际**吸收量（必须允许 < damage，不能私自吞掉未吸收部分）。
- **`AbsorbByStateMixin`**：把宿主修饰器状态当作伤害池。**必须挂在修饰器上**——ability 级状态是施法者共享的，一个技能给多目标加盾会共用同一份池子。它不存任何数值，池子大小/回复/破零反应全在修饰器状态字典与配置里。分两步：受击前 `OnBeforeBeAttack` 判定资格并 `AttackResult.RegisterAbsorb`（此刻还不知道伤害，不能扣）；真正结算时 `AbsorbDamage` 按实际伤害扣池子。
- **`AttackResult`**：最终伤害算出后、扣血前按优先级依次抵扣已登记的 `IDamageAbsorber`；`absorbEntries` 容量 8（多面盾同时挂在一个单位上），超出丢弃并告警（静默丢一面盾 = "某类伤害突然开始掉血"，极难定位）。
- **破盾出口**：`DoActionOnSpecialsChangeMixin` 监听对应 `Key` 越过阈值（用"跨入条件"触发模式，破盾必须用这个，避免任何一次写成 0 都重复触发）。

> 写状态用 `SetSpecial` / `AddSpecial`，读用 `SpecialValue`，二者通过 `Target`（Auto/Modifier/Ability）对称选层。

## 六. 层数消耗与状态比较

`RemoveModifierByTag` 由"按标记整条净化"扩展为"按标记逐层消耗"，并新增 `BySpecialCompare` 谓词。

### 1. `RemoveModifierByTag` 重构为三模式

| 模式（`StackRemoveMode`） | 语义 | `CountExpr` |
|--------------------------|------|-------------|
| `Consume`（默认） | 消耗 N 层（引爆 / 逐层衰减） | 必填 |
| `Clear` | 清空全部层数 → 帧末整条摘除（净化/驱散） | 忽略 |
| `Keep` | 减到只剩 N 层 | 必填 |

字段：`Tags`（目标标记，跨来源跨 ability）、`CountExpr`（层数，`OperatorValue` 可写 `TagStackValue(Burn)*0.5` 消耗当前层数一半）、`Mode`、`ResultKey`（把**实际消耗层数**写进 `AbilitySpecials`，供同一条 Actions 后续按消耗量结算伤害；读回 `SpecialValue` 显式填 `Target=Ability`，否则 Auto 在有 modifier 上下文会优先读修饰器层而读不到）。

**时序（关键）**：层数与 `Properties` **同步立即**回退，`ControlComponent.Rebuild` 会跳过 0 层实例，因此 `tagMask`/`tagStacks`/`IsControlled` **同帧**就释放（旧版净化整条等一帧，同一条 Actions 后续读 `IsControlled` 会拿到旧值，这里没有这个坑）。归零实例由 `AbilityComponent.ScheduleFlushPendingRemoves()` 帧末统一 `Dispose`，只改数字不动链表，不会在别人遍历 `modifiers` 或 `Rebuild` 广播栈里改集合。

### 2. 迟摘除与单一真相源（`ActorModifier`）

- `StackCount` 是层数唯一真相源；`ReduceStack(take)` 同步减层并返回实际减掉层数，**不摘除**。
- 归零只置 `IsPendingRemove`；帧末 `FlushPendingRemove()` 真正摘除（若这一帧内又被 `TryAddStack` 续上，则只清标记不摘除）。
- `ControlComponent.Rebuild` 遍历时跳过 `StackCount<=0` 的实例，避免"标记在但层数为 0"的半生效态。
- `AbilityComponent` 在批量摘除期间用 `suppressNotify` 把多次 `RemoveModifier` 通知合并成一次重建，否则清 5 层会触发 5 次全量 Rebuild。
- 减层按"最早到期优先"（无限时长排最后，永不被优先削掉），符合"自然衰减"直觉。

### 3. `BySpecialCompare` 谓词

读状态字典值与阈值比较（区别于读实体级数值的 `ByNumericCompare`）。`Value` 填 `BaseValue`（单值用 `SpecialValue`，比例用 `OperatorValue`）；读写层由 `SpecialValue.Target` 决定，与 `SetSpecial`/`AddSpecial` 共用 `TargetHelper.ResolveSpecialTarget` 不会错层。典型用法：盾量>0 才允许破盾反击、免疫次数==1 改播"最后一挡"、灼烧>=3 才允许引爆（配合 `RemoveModifierByTag` 消耗层数）。

## 七. 霸体 / 破霸体

- **`ConfigNumericBreak`**：一条削韧配置 = 打击部位 × 属性名 × 削韧值（扁平三元组，编辑器里就是一张三列表格，不用字典套字典）。`NumericKey` 填属性表 Key 列的**组首名**（"EN"）而非段位（1012/10121），避免填段位歧义改上限。
- **`AttackHelper.ApplyNumericBreak`**：命中时按 `HitBoxType` 与属性查配置并写入数值。
- **`ByNumericCompare` + `SetNumericValue`**：`DoActionOnNumericChangeMixin` 监听 `NumericComponent` 数值变化（如韧性归零 → 触发硬直/处决）。注意它监听的是实体级数值池，与"每目标各一份"的修饰器状态（走 `DoActionOnSpecialsChangeMixin`）数据源不同。

## 九. 设计原则速记（配表/排错用）

1. **状态固有属性写进标记本身**：剥夺/上限/等级/打断全在 `GameplayTagMeta`，每条修饰器不各配一份 → 同源状态行为永远一致。
2. **上限/等级属于标记，不属于修饰器**：多来源挂同一标记时聚合上限、动画一致。
3. **层数只有 `StackCount` 一份真相**：别在状态字典另存一份层数。
4. **数字同步、结构延后**：减层立即改数字（供同帧后续 Action 读），摘除放到帧末，避免遍历链表/广播栈时改集合。
5. **两条轴互不相通**：被控问 `IsControlled`，能动能放技能问 `CanDo`。
6. **读写层对称**：`Set/AddSpecial` 与 `SpecialValue` 用同一套 `Target`，写哪层就从哪层读。
7. **专盾先于通用盾**（`AbsorbPriority`），否则通用盾吞光伤害。
8. **失败要显眼不要安静**：`TagStackValue.Min` 默认 1、`SpecialValue` 读不到就报错返回 `Default`、`absorbEntries` 超容告警 —— 都比"静默 0 伤害"好查。
9. **方向不同的属性不要挤进同一根轴**：被选中性 / 强制目标走 `selectOf` / `forcedOf`，"能不能动"走 `tierOf`，两者加载期互斥校验。
10. **强制要软不要硬**：嘲讽目标失效即回落常规选敌；硬锁会在目标消失时把人钉死。
11. **状态能叠加就拆开**：虚化（不可选中）与无敌（伤害拦截）是两个状态，分开配才能表达"AOE 命中但被吞"。
